Leé con calma: «Un médico atiende muchos pacientes y cada paciente es atendido por un solo médico». 2 · MER

✍️ Ejercicio 2.1: de N:M a las FK Medio

Un cliente compra muchos productos y un producto puede ser comprado por muchos clientes. Escribí las entidades en singular —cliente, producto y la intermedia compra— con el tipo de cada columna (INT, VARCHAR, DECIMAL, DATE), la PK de cada entidad y las dos FK en compra que apuntan a cliente y producto. fecha va como DATE y cantidad como INT. En SQL esas tablas se escriben en plural: clientes, productos y compras. Usá el menú para insertar las entidades, los atributos, las marcas PK/FK y las líneas. Las líneas no se agregan solas. Primero hacé clic en la entidad o línea que quieras dejar atrás y después apretá Línea de relación, 1 a N o N a 1: la línea aparece justo ahí, entre las entidades, con la cardinalidad elegida (o vacía para escribirla vos).

Menú para armar el MER

✍️ Ejercicio 2.2: una relación 1:N en tablas Medio

Un cliente hace muchos pedidos y cada pedido pertenece a un solo cliente. Escribí las dos entidades del MER en singular, con el tipo de cada columna: cliente(id_cliente PK INT, nombre VARCHAR(50)) y pedido(id_pedido PK AI INT, fecha DATE, id_cliente FK INT). La FK id_cliente va en pedido porque es el lado N: es quien tiene que recordar a su cliente. Escribí también la cardinalidad 1──N entre las dos entidades. No hace falta crear tablas todavía: esto es el MER.

✍️ Ejercicio 2.3: multivaluado y derivado Difícil

Un cliente tiene varios teléfonos y queremos mostrar su total de compras, que se calcula sumando los importes. Explicá y escribí cómo queda el MER: el cliente con id_cliente PK INT y nombre VARCHAR(50); una tabla telefono con id_telefono PK INT, numero VARCHAR(20) y id_cliente FK INT (un teléfono por fila); y una aclaración de que el total no se guarda porque es un atributo derivado que se calculará con SELECT. Escribí la cardinalidad 1──N entre cliente y teléfono.

✍️ Ejercicio 2.4: relación 1:1 con UNIQUE Difícil

Un alumno tiene una sola libreta y cada libreta pertenece a un solo alumno. En el MER, la FK va en la tabla que depende de la otra y lleva UNIQUE para que un alumno no pueda tener dos libretas. Escribí: alumno(id_alumno PK INT, nombre VARCHAR(50)) y libreta(id_libreta PK INT, id_alumno FK INT UNIQUE, fecha DATE), más la cardinalidad 1──1. Explicá con tus palabras por qué la FK está en libreta y no en alumno.

4 · Consultas (SELECT)

Todas las consultas de este apartado se hacen sobre una sola tabla llamada productos(id_producto, nombre, precio, stock). No hace falta JOIN. En las actividades 3, 4 y 5 primero tenés que crear esa tabla con CREATE TABLE y después escribir la consulta. Presioná ✅ Corregir en cada ejercicio.

✍️ Ejercicio 4.1: filtrar con WHERE Fácil

WHERE deja pasar solo las filas que cumplen una condición. Escribí un SELECT que muestre nombre y precio de los productos cuyo nombre sea exactamente 'Cuaderno'. Usá WHERE nombre = 'Cuaderno'.

✍️ Ejercicio 4.2: ordenar con ORDER BY Fácil

ORDER BY ordena el resultado. Por defecto es de menor a mayor (ASC); para de mayor a menor se agrega DESC. Mostrá nombre y precio de todos los productos, ordenados de mayor a menor precio.

✍️ Ejercicio 4.3: comparar con > Fácil

Primero creá la tabla con CREATE TABLE productos: id_producto como PK entero, nombre VARCHAR(50), precio DECIMAL(10,2) y stock INT. Después, el signo > compara valores numéricos: escribí una consulta que devuelva nombre y stock de los productos con más de 10 unidades en stock, usando WHERE stock > 10.

✍️ Ejercicio 4.4: comparar con < Fácil

Volvé a crear la tabla con CREATE TABLE productos (id_producto PK, nombre VARCHAR, precio DECIMAL y stock INT) para practicar también la creación. Después, el signo < es el contrario de >: mostrá nombre y precio de los productos que cuestan menos de 1000, con WHERE precio < 1000. No incluyas los que cuestan exactamente 1000.

✍️ Ejercicio 4.5: limitar con LIMIT Medio

Volvé a crear la tabla con CREATE TABLE productos (id_producto PK, nombre VARCHAR, precio DECIMAL y stock INT). Después, LIMIT corta la cantidad de filas que devuelve la consulta: escribí una consulta que muestre nombre de los 5 primeros productos ordenados alfabéticamente. Necesitás ORDER BY nombre y, al final, LIMIT 5.

✍️ Ejercicio 4.6: buscar con LIKE Medio

LIKE busca patrones de texto. El símbolo % significa «cualquier cantidad de caracteres». Mostrá nombre y precio de los productos cuyo nombre empieza con «Cu»: WHERE nombre LIKE 'Cu%'.

✍️ Ejercicio 4.7: contar con COUNT Medio

COUNT(*) cuenta filas. Escribí una consulta que devuelva una sola columna con el nombre cantidad_productos y el total de productos de la tabla: SELECT COUNT(*) AS cantidad_productos FROM productos;.

✍️ Ejercicio 4.8: evitar repetidos con DISTINCT Medio

DISTINCT saca los valores repetidos del resultado. Muchos productos pueden tener el mismo stock. Mostrá la lista de stocks distintos sin repetir: SELECT DISTINCT stock FROM productos;.
